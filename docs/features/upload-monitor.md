# 上传监控窗口

状态：**仅方案，尚未实现**。

本文是 AtomGit CLI 对 resumable 多文件上传进行只读监控的正式特性说明。
当前源码已经包含 LFS 慢流检测和连接恢复策略，但尚未提供下文所列的
`atomgit monitor` 命令、会话快照或独立监控窗口。文档中的命令和状态字段
代表已采纳的后续设计，不能作为当前版本的已提供能力。

## 1. 目标与边界

为大批量、并行、可恢复上传提供一个独立终端中的观测窗口，帮助用户回答：

- 当前上传会话是否仍在推进；
- 每个并行 Flow 的即时速度和正式策略速度是多少；
- 某个 Flow 是否已经建立可靠基线并持续低速；
- 是否进入等待替换、重连后验证或自动替换停用阶段；
- 连接替换是否改善了速度；
- 上传结束后最终完成、失败和替换统计是什么。

监控只复制和解释上传状态，不参与上传决策。它不能暂停、取消、重启、
改变批次、修改远端内容或强制触发连接替换。这里的“替换”是替换当前
LFS 对象的请求连接，不是重启 CLI 进程；健康 Flow 和其他 worker 继续运行。

本特性面向上传中的文件传输速度，不是远程仓库下载速度监控。未来如果需要
下载监控，应在同一 `monitor` 顶层命令下增加独立的 `download` 监控对象，
不能把两者的状态字段混用。

## 2. 用户入口

监控能力位于顶层 `monitor` 命令下，而不是 `upload` 命令组下。当前只保留
以下三个入口：

```bash
atomgit monitor upload status
atomgit monitor upload status --list
atomgit monitor upload status SESSION_ID
```

### `atomgit monitor upload status`

持续监控默认上传会话。行为等价于先取得会话摘要列表，再选择列表中的第一个
会话作为目标。会话排序必须确定：活动会话优先，同一类别按最近更新时间倒序。

- 每秒左右刷新一次；
- 展示会话摘要、Flow 状态和最近关键事件；
- `Ctrl+C` 只关闭监控窗口，不给上传进程发送停止信号；
- 没有可监控会话时输出明确提示并退出。

### `atomgit monitor upload status --list`

一次性列出活动会话和保留期内的近期会话摘要，用于发现 `SESSION_ID`。
它只展示会话层，不展开每个 Flow 的明细，输出后退出。

建议字段如下：

```text
SESSION  状态    开始时间  批次    活跃/峰值Flow  替换  最近更新
a84f21   上传中  14:00     2/18    5/5            1     2秒前
9c117e   成功    09:10     18/18   0/5            2     11:42
```

### `atomgit monitor upload status SESSION_ID`

持续监控指定会话。它不会自动切换到其他会话，适合多个上传任务并行时固定
观察其中一个任务。活动会话和已经结束、仍在保留期内的会话都可以被指定。

不提供 `--watch` 选项，也不提供单独的一次性详细快照命令；这两个入口本身
就是持续监控入口，`--list` 才是一次性列表命令。

## 3. 监控层级

一次 `atomgit upload` 目录上传对应一个 `SESSION_ID`。会话下包含若干并行
Flow，每个 Flow 代表一个正在传输或曾经传输过的 LFS 对象请求。

会话层保存：

- 会话 ID、状态、开始/结束时间和最近更新时间；
- 当前批次/总批次、文件总数和已确认文件数；
- 总字节数和已确认字节数；
- 活跃 Flow 数、峰值 Flow 数；
- 累计连接替换次数、替换后改善成功次数和自动替换停用次数；
- 最近关键事件。

Flow 使用会话内匿名编号，例如 `Flow-01`。状态不得保存源路径、远端路径、
仓库名、URL、请求头、token 或完整 LFS OID，因此 Flow ID 只用于关联同一个
对象的多次状态更新。

## 4. Flow 监控字段

### 4.1 即时速度 `sample_speed`

约 5 秒的显示速度：

```text
sample_speed = sum(有效消费的应用层 payload 字节) /
               sum(本地有 payload 可供消费时的网络等待时间)
```

它用于及时反馈，不参与连接替换判断，避免单个短样本的网络抖动触发策略。

### 4.2 正式速度 `window_speed`

约 30 秒正式策略窗口的速度：

```text
window_speed = 30 秒窗口累计有效 payload 字节 /
               累计有效网络等待时间
```

这是应用层 payload 消费速度，不是整台机器的网卡总流量，也是慢流判断和
策略解释使用的主要速度。

### 4.3 自身稳定基线 `stable_baseline`

记作 `O`。最近三个稳定正式窗口的速度分别为 `S1`、`S2`、`S3` 时，只有相邻
窗口变化均不超过 20% 才形成基线：

```text
abs(S2 - S1) <= 0.20 * S1
abs(S3 - S2) <= 0.20 * S2
O = median(S1, S2, S3)
```

例如 `40, 42, 39 MiB/s` 可以形成约 `40 MiB/s` 的基线；`40, 20, 39 MiB/s`
波动过大，不形成可靠基线。后续稳定窗口可以滚动更新自身基线。

### 4.4 健康同伴基线 `peer_baseline`

记作 `P`。对当前候选 Flow 以外的活跃 Flow，在最近三个正式窗口分别计算
同伴速度中位数 `M1..M3`。每个窗口至少有两个同伴落在该窗口中位数的
70%～130% 范围内，且 `M1..M3` 相邻变化不超过 20%，才形成：

```text
P = median(M1, M2, M3)
```

同伴不足或同伴不稳定时显示 `--`，不得制造同伴比较结论。

### 4.5 低速窗口 `slow_windows`

有可靠同伴基线时，正式窗口必须同时满足：

```text
S <= 0.30 * P
S <= 0.50 * O
```

没有同伴基线时使用：

```text
S <= 0.30 * O
```

连续满足时显示 `1/3`、`2/3`、`3/3`；任何不满足的窗口都会归零。
`3/3` 只表示进入连接替换候选阶段，仍须通过预计收益、冷却、剩余时间、
改善要求和替换次数上限检查。

### 4.6 连接替换 `replacement_count`

显示为 `n/3`。只有恢复策略正式批准当前 Flow 的连接替换时才增加。普通建连、
切换到下一个对象和批次切换不计入。达到三次或改善验证失败后可能停用自动替换，
但不会因此停止整个上传。

### 4.7 剩余字节 `remaining_bytes`

这是“当前请求估计剩余”，不是保证单调下降的全局进度：

```text
remaining = max(
    0,
    对象总字节 - 服务端已确认 part 字节 - 当前尝试已消费字节
)
```

basic PUT 替换后从对象起点重传，数值可能回升；multipart 保留同一 action 中
已经确认的 ETag，只重试未确认 part。

### 4.8 阶段 `phase`

内部状态映射为：

- `建立基线`；
- `稳定`；
- `疑似低速`；
- `等待替换`；
- `重连后验证`；
- `已恢复`；
- `自动替换已停用`；
- `完成`；
- `失败`。

### 4.9 决策解释和陈旧状态

`last_decision` 保存最近一次策略解释，例如：

- `低速窗口不足`；
- `预计收益不足`；
- `等待 60 秒冷却`；
- `剩余数据过少`；
- `新连接未达到 2 倍改善`；
- `替换后未达到改善要求`；
- `自动替换次数已用尽`。

`updated_at` 用于显示“2 秒前更新”。超过陈旧阈值时显示“状态可能陈旧”，
但不能仅据此宣告上传失败。

## 5. 趋势与界面

每个 Flow 保留最近 12 个正式窗口，即约 6 分钟，使用固定长度环形数组。
不能按每个 Flow 的历史最大值独立缩放，否则不同绝对速度会被错误显示为同样高。

使用绝对速度和相对可靠基线百分比同时表达：

```text
reference = peer_baseline（存在时），否则 stable_baseline
ratio = window_speed / reference
```

所有 Flow 使用统一分段：

```text
▁  0%～15%       ▂  15%～30%      ▃  30%～50%
▄  50%～70%      ▅  70%～90%      ▆  90%～110%
▇ 110%～130%     █  >=130%
```

预期的监控画面：

```text
会话 a84f21 | 上传中 | 批次 2/18 | 最近更新 1 秒前
活跃 Flow 3 | 正式窗口速度合计 69.2 MiB/s | 累计替换 1

Flow  5秒速度    30秒速度   相对基线  低速  替换  最近6分钟    状态
01    41.2 MiB/s 40.8 MiB/s 102%      0/3   0/3   ▆▆▆▆▆▆▆▆   稳定
02     0.3 MiB/s  0.4 MiB/s   1%      2/3   0/3   ▆▆▅▄▂▁▁▁   疑似低速
03    28.4 MiB/s 28.0 MiB/s  70%      0/3   1/3   ▆▂▁▃▄▅▅▅   重连后验证

最近事件
14:31:00 Flow-03 已替换当前连接，开始改善验证
14:32:00 Flow-02 持续低速，2/3
```

窄终端可以隐藏基线列并缩短趋势，但必须保留精确速度、低速计数、替换计数
和当前阶段。

## 6. 数据通路与无干扰原则

采用“最新状态覆盖 + 有界关键事件”的双通路：

```text
上传 worker
  ├─ 覆盖每个 Flow 的最新状态槽位
  └─ 追加低频关键事件
           ↓
      非阻塞内存发布器
           ↓
  合并并原子替换本地会话快照
           ↓
  独立 monitor 进程只读并渲染
```

每个 Flow 只有一个最新状态槽位。普通 5 秒样本、每次 payload 读取、重复稳定
状态和普通剩余字节变化不进入事件队列。关键事件才进入有界队列，建议最多保留
最近 200 条；队列满时淘汰最旧事件。替换次数、阶段和最终结论仍保存在最新
状态及会话累计值中。

上传热路径只做非阻塞内存更新。观测锁不可用、发布器繁忙、状态目录不可写或
序列化失败时，可以合并或丢弃可替代的中间显示采样，绝不等待磁盘，也不改变
上传结果。后台发布器最多每秒原子写一次快照；状态变化可以唤醒发布器，空闲时
每两秒刷新心跳。监控窗口默认每秒重绘。

监控进程只读快照，不持有上传 worker 的内部对象，也不向上传进程发送控制信号。
因此监控进程崩溃、`Ctrl+C`、快照删除或监控状态暂时不可读，都不能中断上传。

## 7. 日志与打印方案

日志分为三种，不把所有采样直接打印到终端。

### 7.1 状态界面

状态界面每秒重绘当前快照，回答“现在怎么样”。它显示会话摘要、Flow 表、趋势
和最近事件，不为每个采样追加一行日志。

### 7.2 关键事件区

只打印低频、有解释价值的变化，例如：

```text
14:30:00 Flow-02 进入低速观察，1/3
14:30:30 Flow-02 持续低速，2/3
14:31:00 Flow-02 已批准连接替换
14:31:02 Flow-02 开始新连接
14:31:32 Flow-02 替换后改善验证通过
```

重复稳定状态、普通速度采样和每次剩余字节变化不打印。

### 7.3 观测警告

观测自身的异常单独显示为 warning，不能伪装成上传失败：

```text
warning: 状态快照暂时不可读，将在下一次刷新重试
warning: 状态已超过 10 秒未更新，状态可能陈旧
warning: 快照字段不完整，已隐藏不可用数据
```

上传失败则显示会话的真实失败状态和最近事件；状态快照写失败只影响观测，不改变
上传命令的退出结果。

## 8. 快照、保留与安全

建议状态路径为：

```text
~/.cache/atomgit/upload-observe/v1/<session-id>.json
```

目录权限为 `0700`，文件权限为 `0600`。发布器先写同目录临时文件，完成后原子
替换正式快照，监控进程不会读到半份 JSON。

状态快照不得包含：

- token、URL、签名 URL、请求头或响应正文；
- 本地源路径、远端路径、仓库名或完整 LFS OID；
- 任何可用于重放远端请求的凭据。

上传结束后默认保留 24 小时。下一次上传或 `status` 命令顺手清理过期观测快照，
不启动常驻清理服务，也绝不删除源文件、上传投影、HF 续传元数据或远端内容。

## 9. 兼容性和验收重点

实现时必须保持：

- 现有 `atomgit upload PATH` 语法和所有既有上传参数；
- 监控进程退出、崩溃、快照删除和状态目录写失败时上传仍继续；
- 多会话选择规则稳定且可解释；
- 快照原子性、权限、保留期和过期清理行为；
- 速度、URL、路径、OID、token 和错误输出的脱敏；
- 5 秒采样、30 秒正式窗口、连续三个低速窗口、收益检查、冷却时间和每对象
  最多三次替换等既有恢复策略完全不变。

离线回归应覆盖：

- 默认会话选择和 `--list` 排序；
- 指定会话持续监控；
- `Ctrl+C` 和监控进程崩溃隔离；
- 快照原子替换、权限、陈旧心跳和保留期清理；
- Flow 字段、趋势和关键事件限长；
- 观测写入失败不影响上传决策；
- 快照和错误输出脱敏；
- 现有上传完整基线未退化。
