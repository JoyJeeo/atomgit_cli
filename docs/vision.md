# AtomGit CLI 项目愿景

## 项目定位

AtomGit CLI 是面向 AtomGit 模型与数据集仓库的命令行工具和 Python
SDK。项目复用 Hugging Face Hub 协议能力，并将端点切换到 AtomGit，以较低
的学习成本提供登录、建仓、上传、下载和数据集访问能力。

这个仓库的 `yuto` 分支是独立开发主线。它可以吸收 AtomGit 上游的变化，
也可以在不等待上游发布的情况下改进功能、测试和用户安装体验。

## 目标用户

- 在终端中管理模型和数据集文件的开发者。
- 需要在 CI 中上传或下载 AtomGit 仓库内容的团队。
- 希望使用类似 `huggingface_hub` 接口访问 AtomGit 的 Python 用户。
- 希望 Git HTTPS 操作复用 AtomGit token 的用户。

## 核心价值

1. **简单**：安装后使用统一的 `atomgit` 命令。
2. **兼容**：明确支持的 Python、HF Hub 和 datasets 版本。
3. **可靠**：上传后可以回读验证，失败信息能够指导用户处理。
4. **安全**：谨慎处理 token、用户文件和全局 Git 配置。
5. **可维护**：CLI 与 SDK 的公共能力具有一致契约和可重复测试。

## 产品边界

本项目不负责：

- 自行实现完整的模型文件传输协议；
- 训练模型或处理数据集内容；
- 替代通用 Git 客户端；
- 默认使用生产仓库执行自动化写测试；
- 管理 AtomGit 之外的用户凭证。

## 成功标准

- model 与 dataset 的创建、上传和下载都有独立测试证据。
- CLI 与 SDK 对相同参数给出一致结果或清楚说明差异。
- 锁定依赖升级或调用变化可以被契约测试及时发现。
- `yuto` 用户能够通过独立、可校验的安装渠道获得对应版本。
- 文档明确区分“代码已实现”“远程已验证”“当前已知问题”和“未来计划”。

## 当前重点

当前阶段优先恢复已经宣传但尚未可靠工作的能力，包括 resumable、revision、
SDK 子目录上传和全局状态恢复；随后将现有自执行测试迁移为标准测试体系，补齐
建仓、下载、Git helper、SDK 和安装包验证。
